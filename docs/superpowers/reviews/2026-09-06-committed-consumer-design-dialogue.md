## Material disagreements and decisions

1. **Authority and API.** Both accepted an independent async `verifyCommittedBatch({repoRoot, taskId})`, exact one-argument/two-key request and required taskId. It reads validated current store -> named TaskState -> unique committed head -> validated v2 inventory preimage. Scratch and producer re-execution provide no post-commit authority. Upstream typed errors survive; consumer judgments use its own error class/codes, including `E_STEP6_SOURCE_STALE` for its source comparison. Success is recursively frozen and includes task/head, batch/inventory digests, base/version/presence, entry count, source digests, resolved finding count and deterministic source ambiguity observations. No captured governance context is returned or accepted.

2. **Historical Git read.** Claude initially called the old contract-check reader private, hardened and clock-free. Codex cited its actual exported synchronous implementation, inherited Git environment, type-only symlink allowance and current-clock historical validation. Claude checked and withdrew all four claims. The accepted producer's hardened raw reader is the extraction reference. A generic exact-tree regular-blob reader will serve BOTH producer and consumer; absence handling and historical decoding stay private. Producer error behavior and its fixed export/request boundaries remain protected. Legacy contract-check fixes are a subsequent integration slice.

3. **One S3.** Claude withdrew the claim that snapshot branding proves freshness. The consumer privately captures one S3 and reads the registry fresh once; pure digest comparison and byte-preserving source search can be shared. Source Check B uses that retained S3. Codex verified a NODE_V8_COVERAGE count mechanism on the existing capture and registry functions without production seams; consumer-specific counts remain to be run. Counts require source inspection too: they do not alone exclude another capture path. Same-instance registry cache mutation is a separate discriminator.

4. **Binding and ordering.** After validated authority, source freshness precedes coverage and semantic proof. One private current T0 is sampled after schema checks and reused; historical B stays clock-free. Pre-side clause/Source resolution and Check A do not impose current activity/expiry. Post-side checks are complete and unwaived: activity, applicability, Source A/B, grant target/owner/expiry and full task-DP scope/ruling coherence. An ASSUM finding's whole binding equals its actual ASSUM pre-tag, including qualifier presence; matching caller evidence and finding to each other is insufficient. Codex accepted Claude's finding that no separate per-entry EXPL suite policy is defined; existing product suite obligations remain for integration.

5. **Actual acknowledgement coverage.** Codex accepted Claude's singleton candidate-preimage proposal when zero groups naming T exist in the authoritative task chain. A known group must match T.subject and T.ackRef, resolve all named evidence, reproduce the actual witness's full group digest, and include the claim. Equivalent groups normalize to one meaning; malformed or conflicting candidates cannot fall back. Global T-id uniqueness does not imply group uniqueness: independent reader controls accepted both equivalent and conflicting duplicate groups. Evidence array permutation follows the sorted typed-ref formula. Duplicate refs are rejected as malformed group input before normalization; contrary to a phrase in Claude's third reply, duplicates do NOT necessarily change the digest because the existing sortTypedRefs deduplicates. No hash formula is changed.

6. **Mode interpretation and corrected reachability.** Claude first proposed reseating one task's immutable base and using newly minted evidence with an old acknowledgement. Codex demonstrated the base immutability, unminted-successor producer refusal, changed base pre-tag and missing acknowledgement membership. Claude explicitly withdrew the construction. Ordinary two-round controls instead retain task/base, mint the successor using EXPL cleanup, retag to the now-existing successor, re-produce and check that the OLD evidence's actual test/body observations still match. A later body change invalidates old evidence; a new matching evidence record still cannot borrow an old acknowledgement that never covered it.

   Codex settles the remaining interpretation in favor of TP's enumerated this-round predicates (786-795) and the one-way historical rule (808), without adding a not-in-B gate. Historical-convergence still requires T and every used successor-chain transition in raw verified B. The two branches are different proofs, not stronger/weaker subsets. The 'this run/round' wording describes the ordinary lifecycle; it is not used to invent a persisted creation-time predicate absent from the detailed contract. Shared C-minus-B lifecycle seed derivation is not imported as a consumer mode gate. Claude suggested a future-task preallocated-evidence construction; its exact transactional reachability has NOT been independently executed or accepted here. No ordinary historical-T positive is claimed on that basis. Any such state must satisfy every enumerated carrier, binding, acknowledgement and outcome condition, and no evidence ref may be forward-missing. This is a recorded implementation interpretation, not a silent specification amendment or new user/panel approval.
