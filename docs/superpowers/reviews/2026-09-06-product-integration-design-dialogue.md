## Reasoned positions and second-round questions

- **Artifact failures:** Claude preferred preserving the previous artifact byte-for-byte, arguing that corrupting old diagnostics is unnecessary because Step6 ignores scratch. Codex accepted preserving old bytes and clarified that no deliberate corruption was intended. Step6 independence alone does not protect Steps1–4 from consuming an older artifact; the current loop must require actual emission success and stop on failure. A separate three-key emitter with canonical temporary-file re-read and atomic replacement is accepted in principle. Exact CLI/return shape, hygiene and symlink/non-file destination handling remain to be specified.
- **Product CLI:** Codex accepted required `--task`, rejection of `--inventory` in provenance mode, one call to the accepted consumer, explicit exit0/1 and unchanged default reporting. Success should carry the verified consumer metadata rather than discard it. Missing or malformed scratch without the rejected flag must remain irrelevant to committed-head success.
- **Legacy API:** Codex accepted an explicit async migration of the raw tree helper to the shared hardened reader, with real callers/tests updated. Removing duplicated Git reading is the rationale; a new async CLI does not force an unrouted old helper to become async. No separate legacy-mode CLI flag is proposed. The old clean-only helper's actual callers and parser boundary must be resolved before implementation, without exempting v1 envelopes from rollout. Historical v1 B and readable legacy records remain independently supported.
- **Review semantics:** General findings are addressed through repair, regeneration, new review and a new committed batch without general findings. Existing findings are not rewritten as handled. Arbiter must receive both committed-source verification and the independent loop gate. Existing general-repair cap2 and provenance-epoch cap8 have separate counters and purposes.
- **Loop correctness:** Codex challenged the first proposal's cumulative cap8, storage of only the last two fingerprints, inclusion of free-form finding prose in progress, and convergence derived solely from the Step6 verdict. Required decisions: per-epoch budget with cumulative total retained; all seen fingerprints within the bounded epoch plus last-two diagnostics; semantic-field normalization so wording changes cannot fabricate progress; and a valid/unlocked loop state in conjunction with a current committed verification. Actual API/state schemas, authorized new-witness checks, initialization and crash recovery are still under discussion.
- **Metrics:** Claude correctly identified missing oracle attribution in the closed inventory, unspecified taggedTests scope, adapter-miss observation and absent-head field spellings. It recommended extending some counts to `unreported`. Codex requested assessment of a separately bound telemetry observation using the component's existing declaration/oracle digest split before weakening mandatory observation to permanent unreported values. No producer/discovery carrier or public context seam is authorized. Adapter failures must distinguish actual typed refusals from non-candidates. The proposed taggedTests scope is inventory entries using head tag when present, otherwise a deleted entry's base tag, explicitly not repository-wide population. Exact unknown/absence spellings and any necessary narrow §11 type amendment must be separately reviewed before ledger code; unobserved data cannot silently become0.

Phase7d2 is read-only and requests concrete decisions for artifact/legacy/CLI work and actual loop/ledger proposals. No agreement is inferred from silence, and no eventual code correction will be retroactively described as prior discussion.

## A–C decisions after the second and third read-only rounds

Phase7d2 completed with exit0 (4 turns, 187.833 seconds), and phase7d3 completed with exit0 (4 turns, 118.352 seconds). Both 154-path freezes stayed unchanged. Claude inspected the actual callers and corrected the assumption that tests imported the old exported helpers: tests invoke the CLI; both `readBaseTreeStoreBytes` and `checkHistoricalBaseProvenance` have no external module callers. Codex accepted explicitly retiring both, without another legacy-mode flag. Their supported historical v1 B and record-reading obligations continue through the accepted consumer/store; no v1 envelope acceptance is preserved.

The artifact operation is `emitChangedTestInventory({repoRoot,baseTreeOid,taskId})` in `changed-test-inventory-artifact.mjs`, returning frozen `{path,inventoryDigest}`. Its CLI uses `--cwd`, `--base-tree`, `--task`, machine JSON and exit0/1. Producer runs before output writes. The emitter validates parent/target redirection, creates missing output hygiene only after successful production, writes/fsyncs/re-reads a sibling temporary file through the canonical v2 reader and verifies its digest before atomic replacement. Existing artifact/ignore bytes remain untouched on pre-replacement failure; a newly created output directory and protective ignore file may remain. Failed production creates neither.

Claude initially argued the head-view hard exclusion made an output ignore file unnecessary. Codex pointed to the independent ordinary-Git hygiene requirement in verification-gate.md:205. Claude explained and accepted the distinction before edits: the emitter creates `.ctide/output/.gitignore` with `*` and `!.gitignore` only if absent, preserves an existing regular file, refuses symlink/non-file carriers, and never rewrites the root ignore file. Steps1–4 require the actual current emission success rather than trusting an old file's existence.

The CLI and public parser move together. `contract-check --provenance --task` calls the committed consumer once and spreads its verified verdict into `{provenance:{status:'pass',...verdict,violations:[]}}`; failures carry status/taskId/coded violations and no invented success metadata. `--inventory` is rejected in provenance mode. Default reporting retains its prior output/exit0. `parseInventory`/`loadInventory` return fully canonical-validated v2 and reject all v1 envelopes with the stable `LEGACY_ENVELOPE_REGENERATE` marker (`legacy-envelope-regenerate`); malformed v2 retains its own diagnostic. The old rollout marker is retired rather than reused with another meaning. Canonical v2 and legacy record-reading authorities remain unchanged.

Codex accepted retiring obsolete v1-scratch PASS and unsupported-v2 product assertions, while requiring useful historical/raw-tree/absence/error handling to remain exercised through the new live CLI or a clearly identified replacement test. Merely deleting the old suite because component tests are green would not demonstrate CLI argument forwarding and error propagation. Current caller/status documentation must announce the CLI/export changes; dated historical decisions remain intact. This release is a bounded integration change, not overall readiness; executable loop state, metrics/types, ledger and final workflow review remain pending.
