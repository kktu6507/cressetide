## Comparison protocol

Use the same exact model ID and effort, CLI, task intent/ACs, starting repository bytes, available tests, tool/network boundaries and per-task resource ceiling. Record actual resolved identities, not aliases alone; unavailable identities limit the claim. Keep top-level and child model settings fixed within each comparison. A model downgrade is a separate experiment. Existing `--lite` policy can down-tier some roles; for a workflow-only comparison fix/disclose that choice rather than accidentally measuring a model change.

After cost observation, possible comparison arms are native agent with normal project instructions (A), current Cressetide default (B), and current Cressetide `--lite` (C), using prespecified A-vs-B and B-vs-C comparisons only when they answer a measured question. A later optimized candidate replaces C for a separate B-vs-candidate experiment; do not conflate existing lite with a new product. Native trials must not be deliberately weakened or receive Cressetide instructions accidentally. Shared project intent is available to every arm; plugin-specific metadata compliance is reported separately from task correctness so native work is not failed simply for lacking plugin artifacts. Pin `CLAUDE.md` and settings visibility explicitly. Default runs are not expected to automatically opt into `--lite`; only truly applicable automatic controls can be counted as missed. TP and high-risk trials belong in later relevant comparisons, not the first small non-TP cost observation.

Fresh sessions and separate repository copies prevent history sharing. Equalize or separately report cold/warm cache regimes; randomized paired order reduces ordering effects but does not prove cache equality. Include all top-level and child usage, cache reads/writes, fresh input, output, retries, failures and repairs; do not double-count cumulative SDK usage. Missing child usage makes cost incomplete, never zero. Report provider-billed amounts when available and separately labelled estimates otherwise. Record elapsed time including coordination and waiting, plus a standardized human-intervention policy and actual human effort. Cost data is for this closed experiment, outside live product ledger/verdict artifacts.

An independent grader controls hidden acceptance checks and predeclared severity definitions. Candidate agents cannot read the hidden checks or answer patch through filesystem, git history, another session, failure memory, decision records, a Map or reconciliation artifacts. Reset and disclose those inputs consistently per arm. Visible intent must remain sufficient to solve the task. Grade outcomes before revealing arm labels where feasible; disclose provenance cues that prevent full blinding. An LLM opinion alone is insufficient: use runnable hidden checks and independent review for behavior they cannot test.

Keep timeout, interruption, tool-error and resource-cap cases in the accounting. Predeclare handling of infrastructure errors and authorized reruns; never replace failed trials silently. Report per-task and per-risk-stratum results rather than a lone pooled average. Small samples and repeated runs on the same task are not independent evidence of broad reliability. The same TP-negative finding or stale replay check in all arms must be framed as an outcome requirement where applicable, not an assumption that native tools implement Cressetide's internal state machine.
